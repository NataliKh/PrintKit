# PrintKit

Бесплатный генератор красивых материалов для печати на А4: упражнения по математике, учебные карточки, именные наклейки, грамоты, расписания и трекеры привычек.

**Сайт:** https://natalikh.github.io/PrintKit/

## Запуск

Это статический проект на HTML, CSS и JavaScript, без сервера и передачи личных данных. Откройте `index.html` или запустите `python -m http.server 8000`.

Проверка логики генераторов:

```bash
node --test tests/*.test.mjs
```

## Автоматическая проверка печати и визуальные образцы

В GitHub Actions перед деплоем запускается Chromium. Браузер создаёт реальные PDF, проверяет количество страниц, формат А4, границы элементов и сохранность примеров при печати.

Каждый запуск создаёт **артефакт `printkit-visual`** (на странице соответствующего запуска во вкладке *Summary → Artifacts*). В архиве находятся:

- `index.html` — галерея всех распечатанных страниц, которую можно открыть локально;
- `manifest.json` — машинно-читаемый перечень тестовых сценариев и результатов сравнения;
- `<сценарий>/sample.pdf` — PDF каждого сценария;
- `<сценарий>/page-N.png` — изображения каждой страницы;
- `baseline-page-N.png` и `diff-page-N.png` — исходная и разностная картинки при сравнении.

В pull request workflow пытается загрузить последние сохранённые образцы из `main` и сравнивает их с текущими. Процент изменённых пикселей и картинки-разницы помогают заметить случайные изменения дизайна. **Визуальное различие само по себе не блокирует релиз** (оно может быть ожидаемым после изменения дизайна); ошибки размеров, печатных страниц и переполнения по-прежнему блокируют деплой.

Эталоны создаются автоматически при первом успешном запуске в `main`. При отсутствии подходящего эталона workflow создаёт новые изображения; артефакты хранятся 30 дней.

Для ручного запуска браузерных тестов (нужны Chromium и утилита `pdfinfo`):

```bash
npm install --no-save --no-package-lock playwright@1.56.1 pngjs@7.0.0 pixelmatch@5.3.0
npx playwright install chromium
node tests/print.browser.mjs
```

Отчёт после выполнения: `artifacts/printkit-visual/index.html`. Генерация тестовых снимков использует **вымышленные демонстрационные данные**, а не личные данные пользователей.

## Реальные миниатюры и SEO-страницы

В каталоге используются **снимки реальных листов А4**, а не условные рисунки: каждый из 24 готовых наборов рендерится Chromium с печатными стилями и сохраняется как JPEG. Эти изображения генерируются во время GitHub Actions и передаются в этап публикации как отдельный артефакт `printkit-thumbnails`. Если изображения недоступны при локальном запуске без сборки, интерфейс сохраняет иллюстративный запасной вариант.

Локальная генерация (после установки зависимостей браузерного тестирования):

```bash
node tests/build-previews.mjs
node tests/seo.browser.mjs
```

Шесть статических страниц `tools/<имя>/index.html` имеют собственные заголовки, описания, FAQ и ссылки в редактор с открытым инструментом и набором. Карта сайта: `sitemap.xml`.

**Важно:** для Google и Яндекса GitHub Pages является сайтом проекта по пути `/PrintKit/`, поэтому `sitemap.xml` следует вручную отправить в соответствующие инструменты вебмастера. Сам факт создания страниц не означает, что поисковые системы уже проиндексировали их.

GitHub Pages публикует только файлы из подготовленного каталога `_site` — без `node_modules`, тестов и промежуточных PDF.

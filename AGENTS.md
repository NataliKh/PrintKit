# Листокия — инструкции для ИИ-агентов

> Прочитайте этот файл перед любым изменением кода. Это действующие правила разработки, а не перечень выполненных задач.

## Репозиторий и продукт
- GitHub: https://github.com/NataliKh/PrintKit (историческое имя репозитория; бренд сервиса — «Листокия»)
- Публичный сайт: https://listokia.ru/
- Основной язык интерфейса: **русский**.
- Продукт: бесплатные генераторы материалов для печати на А4 без регистрации. Целевая аудитория: родители, учителя, школьники и другие люди, которым нужны печатные шаблоны.
- Приоритет: **качество печати, удобство, полезность и скорость работы**, затем дополнительные функции и SEO.
- Публичные canonical, OG, sitemap и robots должны указывать на `https://listokia.ru/`, не на прежний путь GitHub Pages.
- Не переименовывайте ключи `printkit`/`printkit.saved.v1` и API `printKitAnalytics` без отдельной миграции.
- Не объявляйте продукт полностью готовым к коммерческому запуску без фактических проверок.

## Текущая архитектура
Статический проект без серверного API и обязательных зависимостей:
- `index.html` — посадочная страница и редактор.
- `style.css` — оформление сайта и `@media print`.
- `app.js` — конфигурации инструментов, формы, состояния и localStorage.
- `render.js` — `renderSheet(mode, get, escape, lines, clamp)`, формирование печатного HTML.
- `tests/smoke.test.mjs` — тесты на Node.js (node:test).
- `.github/workflows/pages.yml` — тестирование и деплой GitHub Pages при push в `main`.

## Генераторы
Идентификаторы `math`, `writing`, `cards`, `labels`, `diploma`, `schedule`, `habits`.
- Математика: 1–5 класс, количество примеров, уровень, ограничение результата, необязательный лист с ответами. В режиме 5/10/20 занятий `mathGeneratePack` создаёт независимые снимки каждого дня, а `renderSheet` сначала печатает все занятия и только затем блок ответов. Не регенерировать пакет при смене плотности, отображении ответов или печати.
- Прописи (`writing`): **в публичной версии доступны только цифры 0–9 и шесть подготовительных элементов письма** (режимы «Цифры 0–9», «Одна цифра», «Элементы письма»). **Все рукописные буквенные режимы и наборы отозваны 03.11.2026**: самодельные SVG-контуры оказались существенно не похожи на настоящую школьную русскую пропись. Архив ошибок сохранён в Git; **не восстанавливайте его без принципиально другого, подтверждённого источника**. В редакторе показано предупреждение. Инструкции для возобновления: `HANDWRITING_QUALITY.md`. Прописи букв, слоги, соединения, слова и имена пока не выпускать; не маскировать неверные формы под «черновой алфавит».
- Карточки 2.0: строки вида `термин — перевод`; три размера сетки А4: 4/8/12 карточек на лист. До печати валидируются обе стороны и длина текста по размеру; ошибки указывают исходную строку. Каталог содержит 32 набора, включая «Времена года», «Школьные принадлежности», «Природа вокруг нас». Односторонний режим показывает оба поля на карточке; двусторонний формирует чередующиеся листы лицо/оборот. Для переворота А4 **по длинному краю** оборот зеркалится по столбцам; **по короткому** — по строкам. Неполные листы сохраняют пустые слоты, чтобы не перепутались стороны. Не удаляйте эти пустые слоты из DOM без пересмотра физической раскладки; считать готовые карточки по `data-card-index`, а не по общему числу `<article>`. Физическое двустороннее совмещение зависит от настроек и механики принтера; пока не проверено на бумаге.
- Контрольный комплект `tools/print-check/`: калибровка 100 мм и 50 × 50 мм (один лист); проверка парных сторон карточек (два листа) для всех размеров и двух типов переворота. Двусторонние тестовые страницы формируются **тем же** `renderSheet("cards")`, без второй реализации зеркалирования. Успех браузерных тестов не подтверждает точность физического принтера.
- P0.5: /tools/print-check/ — контрольный лист с 100 мм линейкой, 50 × 50 мм квадратом и тестовыми двусторонними карточками. Регистрационные крестики находятся на обеих сторонах в одинаковых симметричных точках; не менять их независимо от режима переворота. Измерения, введённые после физической печати, обрабатываются локально и не сохраняются.
- Наклейки: имя, подпись, количество.
- Грамоты: тип, имя, текст, подписант.
- Расписание: каждый день — строка, занятия разделены запятыми.
- Трекер привычек: названия привычек, число дней (1–31).
- Для карточек, наклеек, грамот, расписаний и трекера привычек существуют палитры: лавандовая, мятная, персиковая, минимализм.

## Стоп-критерий для школьных букв

Не считайте пройденные Node/Chromium тесты доказательством правильной буквы. Геометрическая проверка A4 подтверждает только отсутствие обрезки. Восстановление генератора **только после визуальной и методической сверки полного набора начертаний** с принятым школьным стандартом и подтверждённой лицензии на используемый источник. См. `HANDWRITING_QUALITY.md`.

## Критические инварианты
1. **Кнопка печати не должна повторно генерировать задания**. Печатать актуальный предпросмотр: если ввод ещё находится в задержке обновления (240 мс), сначала завершить обновление без создания новых математических заданий. Новые задания — только по явному нажатию «Обновить лист» или изменению настроек.
2. Всегда экранируйте ввод пользователя перед добавлением в HTML. Не вводите `innerHTML` из пользовательских строк без экранирования.
3. По возможности обрабатывайте данные **локально в браузере**. Не отправляйте имена детей и пользовательские данные третьим сторонам.
4. Печатный результат должен помещаться на А4, не терять строки, не обрезать элементы. Для расписания и трекера привычек реализована адаптивная пагинация целых строк по реальной высоте листа; одиночная непомещающаяся строка блокирует печать. Для наклеек и грамот выявляется скрытое обрезание текста. Заголовки, математические задачи и ответы проверяются по геометрии фактических текстовых фрагментов относительно внутренних полей A4; критическое переполнение блокирует печать. Универсальная пагинация остальных генераторов пока не гарантируется.
5. В математике ответы должны соответствовать выражениям, оставаться целыми и находиться в заданном диапазоне.
6. Трекер привычек: у первой колонки отдельный `<col class="habit-name-col">` (27% ширины); дни — `habit-day-col`. Не возвращайте текстовую колонку в равномерную таблицу с переносом названий по буквам. Проверяйте 30 и 31 день.
7. Адаптивный предпросмотр не должен менять геометрию печатной страницы. Не полагайтесь исключительно на CSS-transform для PDF.
8. Сохраняйте русскую локализацию и доступность (labels, семантические таблицы, управление с клавиатуры).
9. Двусторонние карточки: сохраняйте геометрию парных лицевых и оборотных листов А4, корректное зеркалирование при двух типах переворота, пустые слоты в конце и порядок «лицо–оборот». После изменения CSS обязательны браузерные замеры координат и PDF-проверки.

## Работа с кодом
- Сначала изучите актуальные файлы из `main`; не считайте прошлые обсуждения точным отражением текущего состояния.
- Меняйте минимально необходимый набор файлов, сохраняйте существующие возможности.
- Не добавляйте сложный стек, backend, ИИ API, регистрацию или оплату без конкретной задачи.
- Для каждой новой возможности добавляйте тест. Запуск: `node --test tests/*.test.mjs`.
- Если изменена печать — дополнительно проверьте результат в браузере: предпросмотр, print preview, экспорт PDF Chromium; `tests/firefox.browser.mjs` отдельно проверяет Firefox с `@media print`, но это не PDF Firefox и не физическая бумага. Проверяйте экран смартфона и A4.
- Проверяйте различные длины текста, 31 день, максимальное количество элементов, экранирование, размер и разрывы страниц.
- Выполненный тест отличайте от предположения. Не называйте «проверкой браузера» чтение DOM/текста без изображения или взаимодействия.
- После записи изменений убедитесь, что GitHub Actions выполнился **success**; не называйте новый релиз опубликованным до успешного деплоя.
- Не перезаписывайте `LICENSE` и пользовательские изменения без причины. Не добавляйте секреты в репозиторий.
- Коммиты — небольшие и осмысленные; предпочтительны `fix:`, `feat:`, `test:`, `style:`, `docs:`.
- При нестабильности выбирайте исправления и регрессионные тесты вместо новых возможностей.

## Продуктовые ориентиры
- Пользователь должен получить качественный готовый к печати материал за 30–60 секунд.
- Большое значение имеют сценарии «родитель готовит упражнения», «учитель распечатывает раздаточные материалы», «наклейки для школы».
- Уже реализованы: ограниченная многостраничность, календарный трекер с выходными, 32 тематических набора, шесть SEO-страниц и необязательная аналитика с согласия. Далее: надёжная общая пагинация, ручная проверка печати, расширение тем и измерение реального использования.
- Цены, трафик, поисковая частотность и рыночный спрос нельзя объявлять подтверждёнными без источников и измерений.

## Definition of Done
Изменение считается законченным, только если:
1. Функция работает для стандартных и граничных входных данных.
2. Проходят автоматические тесты, включая новые.
3. Проверены затронутые пользовательские сценарии и печать (или явно обозначено, что визуальная проверка недоступна).
4. Деплой успешен, если код публиковали в `main`.
5. В отчёте названы реальные изменения, ограничения и ссылки на коммит/запуск.

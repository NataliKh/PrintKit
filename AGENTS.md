# PrintKit — инструкции для ИИ-агентов

> Прочитайте этот файл перед любым изменением кода. Это действующие правила разработки, а не перечень выполненных задач.

## Репозиторий и продукт
- GitHub: https://github.com/NataliKh/PrintKit
- Публичный сайт: https://natalikh.github.io/PrintKit/
- Основной язык интерфейса: **русский**.
- Продукт: бесплатные генераторы материалов для печати на А4 без регистрации. Целевая аудитория: родители, учителя, школьники и другие люди, которым нужны печатные шаблоны.
- Приоритет: **качество печати, удобство, полезность и скорость работы**, затем дополнительные функции и SEO.
- Не объявляйте продукт полностью готовым к коммерческому запуску без фактических проверок.

## Текущая архитектура
Статический проект без серверного API и обязательных зависимостей:
- `index.html` — посадочная страница и редактор.
- `style.css` — оформление сайта и `@media print`.
- `app.js` — конфигурации инструментов, формы, состояния и localStorage.
- `render.js` — `renderSheet(mode, get, escape, lines, clamp)`, формирование печатного HTML.
- `tests/smoke.test.mjs` — тесты на Node.js (node:test).
- `.github/workflows/pages.yml` — тестирование и деплой GitHub Pages при push в `main`.

## Генераторы
Идентификаторы `math`, `cards`, `labels`, `diploma`, `schedule`, `habits`.
- Математика: 1–5 класс, количество примеров, уровень, ограничение результата, необязательный лист с ответами.
- Карточки: строки вида `термин — перевод`.
- Наклейки: имя, подпись, количество.
- Грамоты: тип, имя, текст, подписант.
- Расписание: каждый день — строка, занятия разделены запятыми.
- Трекер привычек: названия привычек, число дней (1–31).
- Для нематематических инструментов существуют палитры: лавандовая, мятная, персиковая, минимализм.

## Критические инварианты
1. **Кнопка печати не должна повторно генерировать задания**. Печатать уже показанный экземпляр. Новые задания — только по явному нажатию «Обновить лист» или изменению настроек.
2. Всегда экранируйте ввод пользователя перед добавлением в HTML. Не вводите `innerHTML` из пользовательских строк без экранирования.
3. По возможности обрабатывайте данные **локально в браузере**. Не отправляйте имена детей и пользовательские данные третьим сторонам.
4. Печатный результат должен помещаться на А4, не терять строки, не обрезать элементы. Для длинного содержимого разработайте полноценную пагинацию; существующая версия её не гарантирует.
5. В математике ответы должны соответствовать выражениям, оставаться целыми и находиться в заданном диапазоне.
6. Трекер привычек: у первой колонки отдельный `<col class="habit-name-col">` (27% ширины); дни — `habit-day-col`. Не возвращайте текстовую колонку в равномерную таблицу с переносом названий по буквам. Проверяйте 30 и 31 день.
7. Адаптивный предпросмотр не должен менять геометрию печатной страницы. Не полагайтесь исключительно на CSS-transform для PDF.
8. Сохраняйте русскую локализацию и доступность (labels, семантические таблицы, управление с клавиатуры).

## Работа с кодом
- Сначала изучите актуальные файлы из `main`; не считайте прошлые обсуждения точным отражением текущего состояния.
- Меняйте минимально необходимый набор файлов, сохраняйте существующие возможности.
- Не добавляйте сложный стек, backend, ИИ API, регистрацию или оплату без конкретной задачи.
- Для каждой новой возможности добавляйте тест. Запуск: `node --test tests/*.test.mjs`.
- Если изменена печать — дополнительно проверьте результат в браузере: предпросмотр, print preview, экспорт PDF; проверяйте Chrome/Firefox, экран смартфона и A4.
- Проверяйте различные длины текста, 31 день, максимальное количество элементов, экранирование, размер и разрывы страниц.
- Выполненный тест отличайте от предположения. Не называйте «проверкой браузера» чтение DOM/текста без изображения или взаимодействия.
- После записи изменений убедитесь, что GitHub Actions выполнился **success**; не называйте новый релиз опубликованным до успешного деплоя.
- Не перезаписывайте `LICENSE` и пользовательские изменения без причины. Не добавляйте секреты в репозиторий.
- Коммиты — небольшие и осмысленные; предпочтительны `fix:`, `feat:`, `test:`, `style:`, `docs:`.
- При нестабильности выбирайте исправления и регрессионные тесты вместо новых возможностей.

## Продуктовые ориентиры
- Пользователь должен получить качественный готовый к печати материал за 30–60 секунд.
- Большое значение имеют сценарии «родитель готовит упражнения», «учитель распечатывает раздаточные материалы», «наклейки для школы».
- Следующие направления (планы, **не реализованы**): многостраничный вывод, библиотека тематических шаблонов, календарный трекер с выходными, отдельные SEO-страницы, измерение использования и конверсии.
- Цены, трафик, поисковая частотность и рыночный спрос нельзя объявлять подтверждёнными без источников и измерений.

## Definition of Done
Изменение считается законченным, только если:
1. Функция работает для стандартных и граничных входных данных.
2. Проходят автоматические тесты, включая новые.
3. Проверены затронутые пользовательские сценарии и печать (или явно обозначено, что визуальная проверка недоступна).
4. Деплой успешен, если код публиковали в `main`.
5. В отчёте названы реальные изменения, ограничения и ссылки на коммит/запуск.
